## 2. Findings

| ID | Finding | Evidence |
|---|---|---|
| A1 | `POST /devices/{id}/algopin/{onetime,hourly}` works with the `YYYY-MM-DDTHH:00:00+07:00` format, `accessName`, `variance`; response `{pin, pinId}`; latency ≈ 350 ms | API |
| A2 | **Deterministic:** an identical request returns the same `pinId` and the same PIN (the research's HYP for igloohome, now confirmed). Re-sending after a lost response is safe | API |
| A3 | `pinId` is a 24-hex value (docs example shows 16 characters) | API |
| A4 | **One-time PIN is single-use on the lock**: the second entry is refused and logged as type 16 "Wrong PIN entered", with the same PIN fingerprint | HW |
| A5 | algoPINs work with no Bridge involvement at creation; the lock validates offline. Logs still reach us through the Bridge within 3–6 s | HW + API |
| A6 | Duration PIN first use is log type 22; one-time use is type 20 (matches LOG_TYPES) | HW |
| A7 | **Active-PIN count rose 4 → 5 only after the hourly PIN's first use**; one-time use did not change it. HYP: activated duration PINs occupy one of the 199 slots until they expire | HW (one sample) · HYP (cause) |
| A8 | PIN fingerprint matching works: every use was linked to its code on the Access page | API |

Not tested: variance difference on an identical window (#2 used v3 only), daily and permanent types, a request that breaks a rule (the form blocks them; server rejects them too), `402` after the trial.
